研究问题

复杂内容生产里，如果按“调研 → 写作 → 审查 → 排版”拆成多 agent 流水线，人只保留“目标定义 + 最终审阅”，能不能显著减少跨环节信息损耗？

Evidence Map 关键结论

  • 橙皮书这类复杂内容生产，当前主要依赖人机混写，缺少结构化流水线 — confidence: high
  • 知识管理的核心瓶颈不是“没有资料”，而是“资料没有进入可复用闭环” — confidence: high
  • 交接协议比模型选择更重要：协议不清时，强模型也会被弱输入拖垮 — confidence: high

多 Agent 流水线设计初稿

角色职责输入输出
调研 Agent收集资料、提炼事实、标注来源主题 + 范围约束调研简报 + 证据清单
写作 Agent基于调研产出结构化初稿调研简报 + 写作规范初稿 + 结构说明
审查 Agent检查事实、逻辑、风格一致性初稿 + 规范 + 调研证据审查意见 + 修改标记
排版 Agent按渠道模板生成最终版式终稿 + 渠道规范排版成品 + 元数据

下一步行动建议

  1. 在橙皮书生产场景中先跑“单环节试点”：只用“写作 + 审查”两段流水线
  2. 建立最小交接协议模板：先固定 topic / evidence[] / constraints[] / final_text 等字段
  3. 定义审查门优先级：先从“事实门”开始，因为橙皮书类内容最痛的是引用失真
